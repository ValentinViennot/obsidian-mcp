## Accepted limitations (record in the archived spec, do not re-fix when re-reported)

- L1 Checkboxes inside HTML comments, `%% %%` comments, or fences nested in blockquotes/callouts are listed (the flat fence grammar does not parse containers or comments).
- L2 Field signifiers are recognised anywhere on the line (last wins), while the plugin reads trailing fields only.
- L3 An invalid date stores NULL, so the task is invisible to `due_by`/`scheduled_by` but visible without a date filter.
- L4 Keyset paging over a live index can miss or repeat a task edited between pages. A note moved mid-pagination may be skipped or repeated on the next page, and a compact-form cursor whose boundary note was deleted or moved is refused, so the caller restarts.
- L5 Freshness is one index pass (default 300 s). `edit_note` does not re-derive tasks.
- L6 Recurrence, created/cancelled dates, dependencies, global filters and custom status configuration are not modelled. Custom markers map to `open`.
- L7 Nesting (parent/child) is not stored.
- L8 Rollback is roll-forward (design L8). A bare redeploy of the version-3 image re-extracts every note, and because it has no version-4 cleaner it also clears every note's embedding certification. The embed pass then re-chunks every note and reuses every stored vector (#281), so no provider calls are made. `semantic_search` shows stale annotations until that pass catches up. `note_tasks` is untouched (cascade still holds), and rolling forward again re-derives every task row.
- L9 `keyword_search` still renders paths raw. The escaped-path rule applies to `list_tasks` only.
